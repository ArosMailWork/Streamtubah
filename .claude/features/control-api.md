# Remote control API (obs-websocket v5 subset)

## Files
- `src-tauri/src/api.rs` — TCP listener + tungstenite; routes `/audio/<name>` to the Audio Bridge,
  `/audio-source/<name>` to Plugin Audio sources, `/plugin` to a permission-limited control session for JS plugins
  (see js-plugins.md), everything else to the control session
- `src-tauri/src/settings.rs` — `ApiSettings` (enabled, port 4455, password generated by `random_token`, allow_lan)
- `src-tauri/src/commands.rs` — `settings_set` calls `api::configure` when API settings change; `api_info`
- `docs/control-api.md`, `examples/control-api/client.py`

## Behaviour
- Auth: base64(sha256(base64(sha256(password + salt)) + challenge)); wrong -> close 4009.
- Never binds 0.0.0.0 without a password.
- Requests lock the Studio mutex on the connection thread. Events come from Tauri `listen` on
  `obs:output`, `studio:scene`, `studio:scenes`, `studio:mute`, `studio:volume`. Those handlers must NOT lock
  Studio (emits happen while Studio is locked), so event payloads carry the data they need.
- Output starts go through `Studio::start_output` (opens a live-only mic first).
- `SetCurrentProgramScene` always goes on air (`scene_set_program`); Studio Mode requests: Get/SetStudioModeEnabled,
  Get/SetCurrentPreviewScene, TriggerStudioModeTransition (code 506 when Studio Mode is off).
- Virtual camera: Get/Start/Stop/ToggleVirtualCam; start returns 500 until the camera was registered once
  from the app (registration needs a UAC prompt, never triggered by a remote client). Event VirtualcamStateChanged.
- Scene collections: GetSceneCollectionList, SetCurrentSceneCollection, CreateSceneCollection.
  Profiles: GetProfileList, SetCurrentProfile, CreateProfile, RemoveProfile. All refuse while any output is active.
- After any successful request that is not `Get*` / BroadcastCustomEvent, `run_request` emits `studio:changed`
  (after releasing the Studio lock) so the UI follows remote scene switches, mutes, etc. Getters are skipped
  because controllers poll them.
- Same port also serves: `/chat` (read-only chat stream, no password) and plain HTTP `GET /overlay/chat`
  (non-upgrade requests are detected with `TcpStream::peek`), see chat.md.
- Password lives in the encrypted vault (see secrets.md); `api_info` no longer returns it. `configure` keeps the
  listener when only the password changes (new connections check it at handshake) and stops + joins the old listener
  thread before binding a new address (previously a restart could fail with "address in use" and leave the API down).
- HTTP on the API port: `/overlay/chat`, `/overlay/alerts`, `/alerts/config`, `/alerts/media/<name>`; WebSocket
  `/alerts` (see alerts.md). `serve_http` reads the peeked request before answering and shuts the socket down
  gracefully (an unread request made Windows reset the connection and truncate larger pages).
